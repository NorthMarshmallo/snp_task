# Распределение дефицита по неделям

Консольная программа строит для независимых кейсов план сборки и отгрузок,
учитывая сроки, запасы, минимальные партии и приоритет заявок. Исходное
задание — в `TASK.html`; принятые решения и ограничения — в `REPORT.md`.

## Запуск

Нужен Python 3.10+. Основной расчёт использует только стандартную библиотеку.
Аргумент — путь к папке с пятью CSV, например:

```bash
PYTHONPATH=src python -m snp data
```

Можно указать другую папку. Справка: `PYTHONPATH=src python -m snp --help`.
Для каждого кейса программа выводит отгрузки, сборку и остатки по неделям,
непокрытый спрос с причинами и итог по заявкам. Чтобы сохранить план в файл,
а предупреждения и ошибки оставить в терминале:

```bash
PYTHONPATH=src python -m snp data > result.txt
```

Чтобы сохранить план и предупреждения в отдельные файлы:

```bash
PYTHONPATH=src python -m snp data > result.txt 2> warnings.txt
```

Коды завершения: `0` — весь спрос покрыт, `1` — есть непокрытый спрос,
`2` — данные не читаются или противоречат контракту, расчёт не начинался.
Запуск исходного набора по выбранным правилам даёт код `1` из-за недостачи.

## Проверки

`uv` создаст окружение и установит зависимости для разработки:

```bash
uv sync --group dev
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
```

`tests/test_cli.py` создаёт отдельный валидный набор, проверяет полный расчёт
с кодом `0`, а затем удаляет временный файл и проверяет отказ с кодом `2`.
Исходные данные при этом не изменяются.
В `tests/test_planner.py` проверки обязательных ограничений и выбранной политики
расположены в отдельных разделах. Политика может измениться после ответов бизнеса.

## Контракт входных данных

Все файлы должны находиться в указанном каталоге и быть в кодировке UTF-8.
Дополнительные столбцы допускаются. Кейсы независимы.

| Файл или правило | Ожидаемые данные и обработка |
| --- | --- |
| `bom.csv` | `component`, `product`, `qty_per_unit`; одна строка, разные имена и положительный расход. |
| `policies.csv` | `parameter`, `value`; обязательны `horizon`, `assembly_lead_weeks`, `assembly_multiple`, без повторов параметров. |
| `stock.csv` | `case_id`, `product`, `initial_qty`; отсутствующий запас считаем нулевым, повтор одного запаса в кейсе отклоняем. |
| `receipts.csv` | `case_id`, `period`, `product`, `qty`; повторные поступления одной позиции в одну неделю суммируем. |
| `demand.csv` | `case_id`, `period`, `request_id`, `priority`, `qty`, `min_lot`; каждая строка — отдельная заявка, даже если `request_id` повторяется. |
| Периоды и сборка | `horizon` — положительное целое; срок сборки — неотрицательное целое; неделя — целая от 0 до `horizon - 1`; кратность положительна. |
| Количества | Неотрицательные конечные десятичные числа; `min_lot` не больше спроса. |
| Приоритеты | Неотрицательные целые; `1` — наивысший, `0` по допущению ниже положительных. |
| Дополнительные позиции | Неизвестные продукты в запасах и поступлениях не используются и отображаются как предупреждение. |
| Ошибки входа | Нет файла или обязательного столбца, пустой идентификатор, неверное число или противоречие правилам выше — код `2`. |

## Архитектура

```text
CSV → input.py → модели Data и Case → planner.py → output.py → терминал
                         ↑                               ↑
                      models.py                    __main__.py
```

`__main__.py` связывает чтение, расчёт и вывод; `models.py` описывает данные;
`input.py` читает и проверяет CSV; `planner.py` планирует один кейс;
`output.py` печатает результат. Тесты находятся в `tests/`.

Допущения, вопросы бизнесу и границы применимости находятся в `REPORT.md`.
